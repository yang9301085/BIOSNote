# OpenClaw 笔记目录说明

这套结构放在 `notes` 下，目的是让人类和 AI 都能快速判断一条内容该落到哪里。

这套分层不是按主题分，而是按“内容状态”和“用途”分：

- 先收集
- 再推进
- 再分析
- 再沉淀
- 最后索引

## 目录约定

- `8_收件箱`：临时记录、待整理素材、随手记。先收再分。
- `1_日记`：按天记录，建议文件名使用 `YYYY-MM-DD.md`。
- `20_项目`：有明确交付物和截止时间的事项。
- `30_研究`：专题调研、问题分析、方案比较。
- `40_知识库`：沉淀后的稳定知识卡片。
- `50_资源`：外部链接、工具、资料索引。
- `90_计划`：周计划、月计划、路线图、复盘计划。
- `99_系统`：模板、提示词、归档规则和系统说明。

## 落笔规则

1. 不确定放哪里时，先放 `8_收件箱`。
2. 有交付目标的内容放 `20_项目`，不是放 `30_研究`。
3. 能长期复用、已经抽象稳定的内容再进入 `40_知识库`。
4. 链接和素材清单优先进入 `50_资源`。
5. 模板、AI 提示词、归档规则统一放 `99_系统`。

## 默认工作流

1. 新内容默认先进 `8_收件箱`，避免一开始就过度分类。
2. 如果内容直接服务于一个明确交付物，整理后进入 `20_项目`。
3. 如果内容是排查、调研、对比、推理过程，整理后进入 `30_研究`。
4. 如果研究结论已经稳定、可复用、可脱离原上下文理解，再提炼到 `40_知识库`。
5. 如果内容主要是链接、工具、文档入口、资料目录，进入 `50_资源`。
6. 如果内容是时间安排、阶段目标、复盘和节奏管理，进入 `90_计划`。

## OpenClaw 默认行为

- 默认保守分类，不要过早写入 `40_知识库`。
- 新对话、新线索、新素材，若还未确认价值或归属，先写进 `8_收件箱`。
- 遇到 BIOS / UEFI / EDK2 / Skia 的问题分析，优先沉淀到 `30_研究`。
- 如果某项研究属于一个正在推进的交付任务，同时在 `20_项目` 保留项目页，并链接对应研究笔记。
- 只有当结论已经脱离具体案例也成立时，才从 `30_研究` 提炼一份简洁知识卡片到 `40_知识库`。
- `20_项目` 关注“要交付什么”，`30_研究` 关注“怎么分析出来”，两者不要混写。

## 推荐命名

- 项目：`项目名 - 阶段.md`
- 研究：`主题 - 调研.md`
- 知识卡片：`概念名.md`
- 计划：`YYYY-W11 周计划.md`、`2026-03 月计划.md`

## AI 分拣提示

如果一条内容同时满足多个分类，优先级建议如下：

`8_收件箱` -> `20_项目` -> `30_研究` -> `40_知识库` -> `50_资源`

如果内容本质是计划安排，则直接进入 `90_计划`，不参与上面的优先级串联。
