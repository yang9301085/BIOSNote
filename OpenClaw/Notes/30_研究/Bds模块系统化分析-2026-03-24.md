### S3 Resume 路径与正常启动分离点

**关键发现：在 Bds 模块中，S3 路径（BOOT_ON_S4_RESUME）与其他路径的分离发生在 RegisterMemoryTypeInformationUpdateCallback() 中：**

```c
VOID RegisterMemoryTypeInformationUpdateCallback(){
    if (   BootMode == BOOT_ON_S4_RESUME
        || BootMode == BOOT_ON_FLASH_UPDATE
        || BootMode == BOOT_IN_RECOVERY_MODE
    ){
        // S3/恢复/闪存路径：仅做 PCIe 桥热复位检查，然后直接返回
        if (IsWarmResetRequiredForPcieBridge()) {
            pRS->ResetSystem(EfiResetWarm, EFI_SUCCESS, 0, NULL);
            ASSERT(FALSE);
        }
        return;  // ← 跳过 ConnectEverything 等
    }
    // 正常路径继续...
}
```

**S3 Resume 行为总结：**
- S3 路径**不执行** ConnectEverything()
- S3 路径**不执行** RunDrivers() / UpdateBootOptionVariables()
- S3 路径**不执行** FastBootHook
- S3 路径**直接跳到** HandoffToTse → ReadBootOptionAndBoot
- S3 特定的 `PreviousMemoryTypeInformation` 在 SaveMemoryTypeInformation() 中被保存/读取

**SignalEndOfDxe() 中的 S3 Save（所有路径均执行）：**
```c
VOID SignalEndOfDxe(){
    EFI_ACPI_S3_SAVE_PROTOCOL *AcpiS3Save;
    if (!EFI_ERROR(pBS->LocateProtocol(&gEfiAcpiS3SaveProtocolGuid, NULL, &AcpiS3Save))){
        AcpiS3Save->S3Save(AcpiS3Save, NULL);  // ← 在 EndOfDxe 前保存 S3 上下文
    }
    SignalEndOfDxeEvent();
    SignalProtocolEvent(&gEfiDxeSmmReadyToLockProtocolGuid);
}
```

## 兵部 — 硬件与设备路径

### ConnectEverything() 设备遍历顺序

```c
VOID ConnectEverything(){
    UINTN i;
    for(i=0; i<NumberOfHandles; i++)
        pBS->ConnectController(RootHandles[i], NULL, NULL, TRUE);
    // + 软盘控制器特殊处理（断开无磁盘的软盘）
}
```

- RootHandles 由 `LocateHandleBuffer(AllHandles, ...)` 获取，顺序取决于系统句柄枚举
- 对每个 Root Bridge Handle 以 **Recursive=TRUE** 调用 ConnectController
- ConnectController 内部负责驱动加载和设备连接递归
- **无 BDS 层级的超时机制**，完全依赖 UEFI ConnectController 的内部实现

### PCI Root Bridge 连接顺序

`ConnectRootBridgeHandles()` 在 `ConnectEverything()` 之前执行（属于 BDS_CONTROL_FLOW 的独立步骤）：
```c
VOID ConnectRootBridgeHandles(){
    Status = pBS->LocateHandleBuffer(ByProtocol, &gEfiPciRootBridgeIoProtocolGuid, ...);
    for(i=0; i<Size; i++)
        pBS->ConnectController(Handle[i], NULL, NULL, FALSE);  // Non-recursive
}
```
- 仅枚举 PCI 总线，**不递归**连接子设备
- 当 `BDS_START_PCI_BEFORE_END_OF_DXE=1` 时，通过 `ConnectRootBridgeHandlesBeforeEndOfDxe` 在 EndOfDxe 之前执行

### NVMe 设备路径识别逻辑

Bds 模块**不包含 NVMe 专用枚举逻辑**。NVMe 设备通过以下标准路径被发现：
1. PCI 总线枚举后，NVMe 控制器驱动（属于 DXE 阶段）在 PCI Handle 上安装 `gEfiNvmExpressPassThruProtocolGuid`
2. SimpleFileSystem 驱动在 NVMe 命名空间上安装文件系统协议
3. BDS 通过设备路径匹配（`LocateDevicePathTest` 等函数）找到启动设备

相关 eLink：
- `LocateDevicePathTest` — 通用设备路径定位
- `PartitionDevicePathTest` — 分区设备路径
- BuildNameFilePath / BuildEfiFilePath — 启动项名称/路径构建

## 刑部 — 异常与风险

### NULL 指针风险点

Bds.c 中有适当的 NULL 检查：
- `ConnectDevicePath()` 入口：`if (pPath == NULL) return;`
- `GetPciHandlesByClass()` 入口：`if (!NumberOfDevices || !HandleBuffer) return EFI_INVALID_PARAMETER;`
- `SaveMemoryTypeInformation()` 中多次使用 `ASSERT_EFI_ERROR()` 和 NULL 检查 HOB 查找结果

### 超时机制完备性

**ConnectEverything() 无内置超时机制：**
```c
VOID ConnectEverything(){
    for(i=0; i<NumberOfHandles; i++)
        pBS->ConnectController(RootHandles[i], NULL, NULL, TRUE);
}
```
- 依赖 `ConnectController` 的 UEFI 内部实现
- 如果某个 PCIe 设备未就绪（如 NVMe 控制器卡在枚举），ConnectController 会**一直等待直到设备就绪或超时**
- 无法通过 BDS 配置调整超时值

### S3 Resume 后 BlockIo 未就绪时的行为（Q8 重点）

**结论：S3 Resume 路径完全跳过 ConnectEverything()！**

```c
// RegisterMemoryTypeInformationUpdateCallback() 中的判断
if (   BootMode == BOOT_ON_S4_RESUME
    || BootMode == BOOT_ON_FLASH_UPDATE
    || BootMode == BOOT_IN_RECOVERY_MODE
){
    if (IsWarmResetRequiredForPcieBridge()) { ... }
    return;  // ← 直接返回，不执行 ConnectEverything
}
```

因此：
- S3 Resume **不调用** ConnectEverything()
- S3 Resume **不等待** BlockIo 就绪
- BlockIo 协议在 S3 Resume 路径中应该**由 S3 Resume 路径的特定驱动层**提供（PEI→DXE 的 S3 恢复路径）
- 如果 S3 Resume 后 BlockIo 未就绪，问题不在 Bds 层，而在上层（PEI S3 Resume 或存储驱动）

### BdsBootFailCount 溢出风险（Q9）

经过搜索整个 `/mnt/f/PBX6000_sample/AmiModulePkg/Bds/` 目录，未找到 `BdsBootFailCount` 变量或相关逻辑。此变量可能存在于：

### BdsSystemResetScheduled 复位链

```
BdsSystemResetScheduled = TRUE  (通过 gAmiResetRequestProtocol->RequestSystemReset)
    ↓
BdsProceedToBootCallback() (ReadyToBoot 事件回调)
    ↓
SaveMemoryTypeInformation(&ResetRequired)
    ↓
if (ResetRequired || BdsSystemResetScheduled)
    → pRS->ResetSystem(EfiResetCold, ...)  ← 冷复位
    ↓
if (IsWarmResetRequiredForPcieBridge())
    → pRS->ResetSystem(EfiResetWarm, ...)  ← 热复位
```

**注意：门下省原计划的 `BdsLibGetVariableAndCheck()` 函数在 Bds 模块中未找到。** `BdsSystemResetScheduled` 标志由 `BdsRequestSystemReset()` 直接设置（line 2736），无需额外变量检查。

## 九大待核实问题解答

### Q1: BdsControlFlowFunctions[] 数组成员和顺序（是否可配置）

**答案：顺序由 eLink BDS_CONTROL_FLOW 定义，编译时固定，但可通过 SDL Token 条件编译控制成员存在与否。**

- BdsControlFlowFunctions[] 在 BdsBoard.c (line 719) 中定义，成员由 Bds.sdl 中的 BDS_CONTROL_FLOW eLink 宏展开
- 顺序在 eLink 中明确定义（从上到下），不可在运行时配置
- 条件编译：各步骤是否包含由对应 SDL Token 控制（如 BDS_CONNECT_CONSOLE_DEVICES=0 时跳过 Connect Console Devices 组）

### Q2: ConnectEverything() 超时机制，PCIe 设备未就绪时处理

**答案：Bds 层无超时机制，依赖 ConnectController 的 UEFI 内部实现。PCIe 设备未就绪时，ConnectController 会阻塞直到设备就绪或底层驱动超时。**

```c
VOID ConnectEverything(){
    for(i=0; i<NumberOfHandles; i++)
        pBS->ConnectController(RootHandles[i], NULL, NULL, TRUE);
    // 无任何超时参数传递
}
```

### Q3: NVMe 在 Bds 阶段枚举顺序和超时

**答案：Bds 模块不包含 NVMe 专用枚举逻辑。NVMe 控制器通过 PCI 总线枚举（ConnectRootBridgeHandles），NVMe 驱动安装 NvmExpressPassThru 协议。Bds 通过标准设备路径匹配识别启动设备。无特殊超时处理。**

### Q4: IsWarmResetRequiredForPcieBridge() 寄存器判断逻辑

**答案：硬编码检查 B/D/F = 0x00/0x1C/0x04 的 PCIe P2P 桥接器。判断逻辑：**

1. 找到目标 Bridge（PciIo on B=0, D=0x1C, F=0x04）
2. 读取 Revision ID，确认 Class Code[3]=PCI_CLASS_BRIDGE 且 [2]=PCI_CLASS_BRIDGE_P2P
3. 检查 Slot Implemented 位：若 Slot 已实现但无设备（Slot Implemented=1, Slot Present=0），跳过热复位
4. 读取 Secondary Bus 和 Subordinate Bus 寄存器
5. 在所有 PciIo Handle 中搜索 Bus 范围在 [SecondaryBus, SubordinateBus] 内的设备
6. 若找到下游设备 → warmResetRequired=FALSE
7. 若未找到下游设备且 Slot 有设备 → warmResetRequired=TRUE

### Q5: MemoryTypeInformation HOB 首启校验逻辑

**答案：通过检查 PreviousMemoryTypeInformation NVRAM 变量是否存在来判断首启。**

```c
Status = pRS->GetVariable(L"PreviousMemoryTypeInformation", ...);
IsFirstBoot = (Status == EFI_NOT_FOUND);  // ← 不存在 = 首启
```

- 若 IsFirstBoot 且 PcdResetOnMemoryTypeInformationChange=TRUE，且检测到运行时内存类型配额变化，则触发重置
- MemoryInformationVariableGuid 可以是 gEfiMemoryTypeInformationGuid（旧版）或 gAmiGlobalVariableGuid（新版），由 HOB 中的 GUIDed HOB 标识

### Q6: S3 Resume 路径与正常启动路径分离点

**答案：分离发生在 RegisterMemoryTypeInformationUpdateCallback() 函数的入口判断处。**

```c
if (BootMode == BOOT_ON_S4_RESUME || BOOT_ON_FLASH_UPDATE || BOOT_IN_RECOVERY_MODE){
    // 仅做 PCIe 热复位检查，然后直接 return
    return;
}
// 正常路径继续执行 ConnectEverything, RunDrivers, UpdateBootOptionVariables 等
```

S3 路径跳过的内容：ConnectEverything、RunDrivers、FastBootHook、UpdateBootOptionVariables、ShadowAllLegacyOptionRoms。
