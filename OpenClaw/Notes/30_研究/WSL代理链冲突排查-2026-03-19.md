# WSL 代理链冲突排查

> [!success] 状态：已解决
> 多层代理/转发链冲突导致的网络问题已排查并解决

---

## 问题现象

- Windows 浏览器访问百度报 `ERR_EMPTY_RESPONSE`
- ping/nslookup 正常，关 VPN 后恢复
- OpenClaw 日志报 `ECONNREFUSED 172.29.80.1:33210`

---

## 根因分析

多层代理/转发链冲突：

1. WSL 里手工设置了代理环境变量 (http_proxy/https_proxy/all_proxy)
2. Windows 侧有 portproxy 转发规则 (33210/33211)
3. VPN 开启后接管流量，和本地代理链冲突

---

## 解决方案

### 1. 删除 Windows portproxy 规则

```bat
netsh interface portproxy delete v4tov4 listenport=33210 listenaddress=0.0.0.0
netsh interface portproxy delete v4tov4 listenport=33211 listenaddress=0.0.0.0
```

### 2. 清理 WSL 代理环境变量

```bash
unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY
```

### 3. 重启 VPN

### 4. 从干净环境重启 OpenClaw

---

## 经验教训

> [!warning] 注意事项
> 1. **不要把临时代理写死进 `~/.bashrc` 等启动脚本**
> 2. **WSL 里 `127.0.0.1` 是 WSL 自己，不是 Windows 宿主机**
> 3. **少用会和 VPN 冲突的本地端口转发**
> 4. **遇到"ping 通但浏览器打不开"，优先怀疑代理链**
