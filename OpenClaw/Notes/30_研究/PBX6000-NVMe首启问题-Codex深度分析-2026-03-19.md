# PBX6000 NVMe 首启问题 - Codex 深度分析

> [!info] 问题概述
> 清 CMOS 后首轮找不到 NVMe，warm reset 后能找到

---

## 核心结论

> [!success] 根因定位
> `PciBus.c` 枚举顺序和 `Bds.c` reset 链组合导致：
> - `EnumerateBus()` 先扫子总线，后做 PCIe link 初始化
> - 首轮冷起时链路还没稳，config read 返回 0xFFFFFFFF → 判定无设备
> - warm reset 后链路稳定，才能扫到

---

## 关键发现

### 1. BDS 首轮 Reset 链 (最明显的软件差异)

**代码位置**: `AmiModulePkg/Bds/Bds.c`

| 行号 | 功能 |
|------|------|
| 1643-1649 | 用 `PreviousMemoryTypeInformation` 是否不存在判断 `IsFirstBoot` |
| 1767-1778 | 首轮且 runtime memory type 变化时置 `ResetRequired=TRUE` |
| 1809-1825 | 先写 CMOS `0x66=1`，再做一次 `EfiResetCold` |
| 1828-1836 | 下一轮启动发现 CMOS `0x66==1`，清零后再补一次 `EfiResetWarm` |

**流程**:
```
清 CMOS 后首轮 (IsFirstBoot=TRUE)
    ↓
BDS 检测到 runtime memory type 变化
    ↓
ResetRequired = TRUE
    ↓
写 CMOS 0x66 = 1
    ↓
EfiResetCold
    ↓
第二轮启动
    ↓
发现 CMOS 0x66 == 1
    ↓
清零 CMOS 0x66
    ↓
EfiResetWarm
    ↓
第三轮 (正常启动)
```

### 2. PciBus 枚举顺序问题 (根因)

**代码位置**: `AmiModulePkg/PCI/PciBus.c`

| 行号 | 功能 |
|------|------|
| 6943-6992 | 对设备做首次 config read；只有 CRS 和 "slot implemented" 的窄场景会补重试 |
| 7413 | 先递归扫桥后设备 |
| 7522-7528 | 真正的 `PcieInitLink(dev)` 才调用 |

**问题机制**:
```
EnumerateBus() 首次扫描
    ↓
读取 NVMe VID/DID (此时链路还没稳)
    ↓
返回 0xFFFFFFFF → 判定无设备 → 跳过
    ↓
后续才调用 PcieInitLink() 初始化链路
    ↓
warm reset 后链路已稳定
    ↓
第二轮扫描能读到 VID/DID
```

## Multi-Agent Triad 分析

### 三个子代理结论

**Baseline Mapper** (PciBus.c 主流程):
- NVMe 没有专门分支，当普通 PCIe endpoint 处理
- 主链: `PciBusStart -> PciEnumerateAll -> StartPciDevices -> InstallPciDevice`

**Differential Comparator** (BDS reset 链):
- 首轮会触发 `cold reset → warm reset` 链
- CMOS `0x66` 作为 reset 标记

**Hypothesis Verifier** (高置信度假设):

1. **冷启动 NVMe ready 太慢，retry 路径太窄**
   - 默认 `LnkTrRetry=5`, `LnkTrTimeout=1000us`
   - M.2 常见 `SlotImpl=0`，retry 不走

2. **链路初始化在扫描之后，没有 rescan 机制**
   - `PciBus.c:7407-7413` 先递归 `EnumerateBus()` 扫子总线
   - `PciBus.c:7522-7527` 后调用 `PcieInitLink()`
   - 没有"链路起来后重新扫描"机制

## EmptyBridgeRecover Patch 验证 (18:48)

> [!warning] Patch 命中了，但不够
> 恢复逻辑确实执行，但 `PcieResetLink() + rescan` 在同一次 DXE 枚举里无法拉起 NVMe

### 日志分析结果

**Cold 阶段 (失败)**:
```
B0:D1C:F4 首次 probe → 0xFFFFFFFF
    ↓
EmptyBridgeRecoverCheck/Reset 执行
    ↓
reset 后再次 probe → 0xFFFFFFFF
    ↓
EmptyBridgeRecoverRescan → Not Found
```

**Warm 阶段 (成功)**:
```
B0:D1C:F4 首次 probe → 0x576510EC (NVMe VID/DID)
    ↓
NVMe 正常安装协议并启动
```

### 下一步建议

在 `EmptyBridgeRecoverReset` 后、`EnumerateBus()` 前打印：
- `LnkSta` - Link Status Register
- `DLLLA/LinkActive` - Data Link Layer Link Active
- `Training` - Link Training Status

**二分判断**:
- `LinkActive=0` → reset 没把链路拉起来
- `LinkActive=1` 但 child 还是全 F → link 已起但 endpoint 还没 ready
