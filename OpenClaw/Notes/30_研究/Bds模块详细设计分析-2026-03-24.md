## 1. 模块概述（位置/职责/文件列表）

### 1.1 位置
- **模块包：** `AmiModulePkg/Bds/`
- **所属层次：** UEFI BDS（Boot Device Selection）阶段
- **编译产物：** BDS 模块，DXE 之后、OS Loader 之前执行

### 1.2 核心职责
Bds 模块是 UEFI 引导流程中的核心枢纽，负责：
1. 初始化控制台设备（ConOut/ConIn/ConErr）
2. 连接所有驱动和设备
3. 枚举可启动设备，构建并维护启动选项列表（BootOptionList）
4. 将控制权移交给操作系统引导加载器或 AMITSE（Setup/Boot Manager）
5. 在特定条件下执行 Reset（冷复位/热复位）

### 1.3 文件列表

| 文件 | 行数 | 主要职责 |
|------|------|----------|
| `Bds.c` | 2741 | 主入口、控制流编排、设备连接、Reset链、引导执行 |
| `BdsBoard.c` | 1007 | 平台级钩子（FastBoot、Shell Boot Option、Platform Override）、BDS_CONTROL_FLOW函数注册 |
| `BootOptions.c` | 2532 | Boot Option 的创建/删除/匹配/排序/NVRAM读写 |
| `AmiPlatformDriverOverrideHooksTemplate.h` | - | 平台驱动覆盖钩子模板 |

### 2.2 BdsEntry 函数（行2122-2199）

BdsEntry 是 `EFI_BDS_ARCH_PROTOCOL` 的实现，由 DXE 调度器在 DXE 阶段完成后调用。执行流程：

```c
VOID BdsEntry(IN EFI_BDS_ARCH_PROTOCOL *This)
{
    PERF_END("DXE"); PERF_START("BDS");
    
    // 1. 初始化"Timeout"系统变量
    InitSystemVariable(L"Timeout", sizeof(UINT16), &DefaultTimeout);
    
    // 2. 注册 LegacyBoot 回调（用于 FPDT 数据记录）
    RegisterProtocolCallback(&gAmiLegacyBootProtocolGuid, ...);
    
    // 3. 获取所有 Root Handle，初始化全局变量
    pBS->LocateHandleBuffer(AllHandles, ..., &NumberOfHandles, &RootHandles);
    BootMode = GetBootMode();
    BdsExecutionPolicy = PcdGet32(AmiPcdBdsPolicyMask);
    
    // 4. 检查外部 OpROM 执行策略
    if (LaunchPolicy == AMI_BDS_POLICY_NO_EXTERNAL_OPROM || ...)
        AmiBdsConnectPolicySetDeviceClassPolicy(..., AmiBdsConnectPolicyDisable);
    
    // 5. 核心：遍历 BdsControlFlowFunctions[] 执行控制流函数
    for(i=0; BdsControlFlowFunctions[i]!=NULL; i++) {
        if (AmiPause != NULL) AmiPause->Pause();  // 支持 Pause 调试
        BiosSerialPrintf("BDS: BdsControlFlow[%u] enter %a func=%p\n", ...);
        BdsControlFlowFunctions[i]();  // ← 实际执行步骤
        BiosSerialPrintf("BDS: BdsControlFlow[%u] exit %a\n", ...);
    }
    
    PERF_END("BDS"); // 正常情况永不返回
}
```

### 2.3 BdsControlFlowFunctions 控制流数组

**关键设计：** `BdsControlFlowFunctions[]` 是一个通过宏 `BDS_CONTROL_FLOW` 扩展的函数指针数组。数组本身定义在 `BdsBoard.c`（行719），内容通过 `.mak` 构建脚本从 `.sdl` 配置文件中提取。这使得各功能步骤可以灵活增减。

**典型控制流步骤**（实际内容由平台 SDL 配置决定，标准 AMI 方案包括）：
1. `ConnectRootBridgeHandles` — 连接 PCI 根桥，触发 PCI 总线枚举
2. `ConnectEverything` — 连接所有设备控制器
3. `ConnectConOutVariable` / `ConnectVgaConOut` — 连接控制台输出
4. `ConnectConInVariable` / `ConnectUsbConIn` — 连接控制台输入
5. `RunDrivers` — 执行 DriverXXXX 列表中的驱动
6. `RunSysPrepApps` — 执行 SysPrepXXXX 应用
7. `PreProcessBootOptions` — 预处理引导选项（孤儿选项策略）
8. `ProcessBootOptions` — 完整处理引导选项列表
9. `PostProcessBootOptions` — 引导选项组后处理
10. `HandoffToTse` — 交控给 AMITSE（正常引导不返回）

## 3. 核心流程

### 3.1 启动设备枚举

#### 3.1.1 PCI 根桥连接（ConnectRootBridgeHandles）

```c
VOID ConnectRootBridgeHandles() {
    // 定位所有 PCI 根桥（gEfiPciRootBridgeIoProtocolGuid）
    pBS->LocateHandleBuffer(ByProtocol, &gEfiPciRootBridgeIoProtocolGuid, &Handle);
    // 连接每个根桥 → 触发 PCI Bus Driver 枚举
    for(i=0; i<Size; i++)
        pBS->ConnectController(Handle[i], NULL, NULL, FALSE);
}
```
**关键作用：** 连接根桥会触发 PCI Bus DXE 驱动执行 PCI 枚举，创建 PCIe/NVMe/AHCI 等设备的句柄（Handle）。

#### 3.1.2 设备控制器连接（ConnectEverything）

```c
VOID ConnectEverything() {
    // 对所有 RootHandles 调用 ConnectController（递归=TRUE）
    for(i=0; i<NumberOfHandles; i++)
        pBS->ConnectController(RootHandles[i], NULL, NULL, TRUE);
    // 特殊处理：软盘控制器断开逻辑
    // （当软盘驱动器未连接时，Disconnect 软盘设备以屏蔽 BBS 软盘启动项）
}
```

#### 3.1.3 Boot Device 枚举（CollectBootDevices / BootOptions.c）

设备枚举的最终目的是为每个可启动设备创建 `BOOT_DEVICE` 结构，加入 `BootDeviceList`：

```c
VOID CollectBootDevices() {
    // 通过 EFI_LOAD_FILE_PROTOCOL 收集（用于 UEFI Shell/网络引导等）
    CollectProtocolDevices(BootDeviceList, &gEfiLoadFileProtocolGuid);
    // 通过 EFI_SIMPLE_FILE_SYSTEM_PROTOCOL 收集（硬盘/USB/光盘等）
    CollectProtocolDevices(BootDeviceList, &gEfiSimpleFileSystemProtocolGuid);
    // 通过 BBS 表收集传统引导设备
    CollectBbsDevices(BootDeviceList);
}
```

`CollectProtocolDevices` 的核心逻辑：
```c
VOID CollectProtocolDevices(DLIST *BootDevices, EFI_GUID *ProtocolGuid) {
    // 找到所有安装了指定协议的所有 Handle
    pBS->LocateHandleBuffer(ByProtocol, ProtocolGuid, &Devices);
    for(i=0; i<NumberOfDevices; i++)
        CreateBootDevice(BootDevices, Devices[i], INVALID_BBS_INDEX, NULL);
}
```

#### 3.1.4 设备过滤（FilterBootDeviceList）

枚举后的设备列表通过 `FilteringFunction[]` ELINK 钩子链进行过滤，可屏蔽特定设备。

```c
    GetEfiVariable(L"BootOrder", ..., &BootOrderSize, &BootOrder);
    for(i=0; i<BootOrderSize/sizeof(UINT16); i++) {
        Swprintf(BootVarName, L"Boot%04X", BootOrder[i]);
        GetEfiVariable(BootVarName, ..., &OptionSize, &Option);
        Boot(Option, BootOrder[i], OptionSize);  // 尝试引导

EFI_STATUS Boot(EFI_LOAD_OPTION *BootOption, UINT16 Number, UINTN Size) {
    Dp = 跳过Header+Description后的设备路径;
    if (Dp->Type != BBS_DEVICE_PATH)  // UEFI 引导
        return BootEfi(Dp, Number, pOptions, Size);
    else                              // 传统引导
        return BootLegacy(Dp, Number);
}

EFI_STATUS BootEfi(..., UINT16 Number, ...) {
    // 1. LoadImage 加载 OS Loader
    pBS->LoadImage(TRUE, TheImageHandle, Dp, NULL, 0, &Handle);
    // 2. 若失败，尝试 DiscoverPartition（从 HD 节点发现完整分区路径）
    // 3. 若还失败，尝试默认路径 EFI_REMOVABLE_MEDIA_FILE_NAME
    // 4. 检查 ImageCodeType == EfiLoaderCode
    // 5. 设置 LoadOptions
    ReadyToBoot(Number);      // 设置 BootCurrent，Signal 事件
    PERF_END("BDS");
    return pBS->StartImage(Handle, NULL, NULL);  // 跳转 OS Loader
}
```

### 3.3 Reset / Cold Reset 链

#### 3.3.1 Reset 链四节点详解

##### 节点1：IsFirstBoot 检测（SaveMemoryTypeInformation 内部，行1551-1700）

```c
VOID SaveMemoryTypeInformation(BOOLEAN *ResetRequired) {
    // 读取 PreviousMemoryTypeInformation
    Status = pRS->GetVariable(L"PreviousMemoryTypeInformation", ...);
    // EFI_NOT_FOUND → IsFirstBoot = TRUE（首次引导）
    IsFirstBoot = (Status == EFI_NOT_FOUND);
    
    // 比较 HOB 中的 MemoryTypeInformation 与当前运行时内存分配
    // 通过 UpdateMemoryUsageInformation() 调整内存类型配额
    if (UpdateMemoryUsageInformation(MemoryInfoHistory, NumberOfMemoryInfoElements)) {
        // 若调整后有运行时内存类型配额变化
        if (IsFirstBoot && PcdGetBool(PcdResetOnMemoryTypeInformationChange)) {
            for (i=0; i<NumberOfMemoryInfoElements; i++) {
                // 若运行时内存类型配额变化 → ResetRequired = TRUE
                if (MemoryInfoHistory[i].Previous != MemoryInfoHistory[i].Next
                    && IsRuntimeMemoryType(MemoryInfoHistory[i].Type)) {
                    if (ResetRequired) *ResetRequired = TRUE;
                    return;
                }
            }
        }
    }
}
```

##### 节点2：BdsSystemResetScheduled 与 AmiResetRequest 协议

```c
// Bds.c 行 195
AMI_RESET_REQUEST_PROTOCOL ResetRequest = {
    BdsRequestSystemReset
};

// Bds.c 行 87-93
EFI_STATUS EFIAPI BdsRequestSystemReset(IN AMI_RESET_REQUEST_PROTOCOL *This) {
    BdsSystemResetScheduled = TRUE;
    return EFI_SUCCESS;
}
```
任何 DXE 驱动或 PEIM 可以通过安装 `AMI_RESET_REQUEST_PROTOCOL` 并调用 `BdsRequestSystemReset()` 来请求系统复位。标志 `BdsSystemResetScheduled = TRUE` 会在回调中触发 Cold Reset。

##### 节点3：BdsProceedToBootCallback 回调（行2006-2028）

```c
VOID EFIAPI BdsProceedToBootCallback(IN EFI_EVENT Event, IN VOID *Context) {
    BOOLEAN ResetRequired;
    SaveMemoryTypeInformation(&ResetRequired);
    
    // 分支A：内存类型信息变化 或 BdsSystemResetScheduled → Cold Reset
    if (ResetRequired || BdsSystemResetScheduled) {
        DEBUG((DEBUG_LOAD, "Resetting the system...\n"));
        pRS->ResetSystem(EfiResetCold, EFI_SUCCESS, 0, NULL);  // ← Cold Reset
        ASSERT(FALSE);  // 永不应返回
    }
    
    // 分支B：PCIe Bridge 热复位需求 → Warm Reset
    if (IsWarmResetRequiredForPcieBridge()) {
        pRS->ResetSystem(EfiResetWarm, EFI_SUCCESS, 0, NULL);   // ← Warm Reset
        ASSERT(FALSE);
    }
    
    pBS->CloseEvent(Event);
}
```

此回调通过 `RegisterMemoryTypeInformationUpdateCallback()` 注册（行2032-2060）：
- 注册到 `gAmiTseEventBeforeBootGuid` 协议事件
- 注册到 LegacyBoot 事件（`CreateLegacyBootEvent`）
- **特殊跳过：** S4 Resume / Flash Update / Recovery 模式下不注册

##### 节点4：IsWarmResetRequiredForPcieBridge（行1802-1996）

```c
static BOOLEAN IsWarmResetRequiredForPcieBridge(VOID) {
    // 1. 查找目标 PCIe P2P Bridge（通过 gAmiBdsPcieBridgeProtocolGuid）
    // 2. 调用 IsPcieBridgeSlotPresent() 检查槽位是否存在设备
    //    （读 PCIe Capability 的 Slot Status Register）
    // 3. 扫描 Bridge 下游所有设备（通过 Secondary/Subordinate Bus）
    // 4. 若 Bridge 存在、槽位空、无下游设备 → WarmResetRequired = TRUE
    // 5. 返回 WarmResetRequired
}
```

**IsPcieBridgeSlotPresent** 逻辑（行1713-1800）：
- 读取 PCI Primary Status 检查 Capability 链表
- 遍历找到 PCIe Capability（CapID = 0x10）
- 检查 SlotImplemented 位和 Presence Detect State 位

## 4. 模块交互（与 PCIe/NVMe/DXE 的关系）

### 4.1 与 DXE 阶段的交互

| 交互点 | 描述 |
|--------|------|
| `PERF_END("DXE")` / `PERF_START("BDS")` | DXE→BDS 性能测量标记 |
| `SignalEndOfDxe()` | Signal `gEfiEndOfDxeEventGroupGuid` 和 `gEfiDxeSmmReadyToLockProtocolGuid` |
| `SignalConnectDriversEvent()` | Signal `gAmiBdsConnectDriversProtocolGuid` 触发驱动连接 |
| `SignalAllDriversConnectedEvent()` | Signal `gAmiBdsAllDriversConnectedProtocolGuid` |
| `CallTheDispatcher()` | 调用 DXE Services 的 `Dispatch()` 调度剩余未执行驱动 |
| `ConnectRootBridgeHandles()` | 触发 PCI Bus DXE 驱动执行 PCI 枚举 |

### 4.2 与 PCIe 的交互

- **PCI 枚举触发：** `ConnectRootBridgeHandles()` → `pBS->ConnectController(RootBridge)` → PCI Bus DXE Driver
- **PCIe Bridge 热复位：** `IsWarmResetRequiredForPcieBridge()` 读取 PCIe Capability 判断槽位状态
- **PCI I/O 协议：** `ConnectVgaConOut()` 使用 `gEfiPciIoProtocolGuid` 查找显示设备
- **PCI 类查找：** `GetPciHandlesByClass(PCI_CL_SER_BUS, PCI_CL_SER_BUS_SCL_USB)` 查找 USB 控制器

### 4.3 与 NVMe 的交互

- **Block I/O 协议：** `CollectProtocolDevices(BootDeviceList, &gEfiBlockIoProtocolGuid)` 枚举所有块设备（NVMe 盘通过此协议暴露）
- **Device Path 匹配：** `LocateDevicePathTest()` / `PartitionDevicePathTest()` 将 Boot Option 与 NVMe 盘句柄匹配
- **简单文件系统协议：** `CollectProtocolDevices(BootDeviceList, &gEfiSimpleFileSystemProtocolGuid)` 收集可启动媒体的 EFI 分区

### 4.4 与 AMITSE 的交互

- **HandoffToTse：** 最终将控制权交给 AMITSE（通过 `AmiPostMgr->Handshake()`），TSE 显示 Boot Manager 界面或直接启动
- **TSE 事件：** `gAmiTseEventBeforeBootGuid` 作为 Reset 链回调的触发事件
- **Boot Manager Policy 协议：** 安装 `gEfiBootManagerPolicyProtocolGuid`，供 TSE 和 OS 调用 `ConnectDevicePath`

### 4.5 与固件更新的交互

- **Flash Update 模式：** `BootMode == BOOT_ON_FLASH_UPDATE` 时使用 `AmiPcdBdsPolicyMaskOnRecoveryAndFlashUpdate` 策略
- **Capsule 处理：** `ProcessCapsulesAfterEndOfDxe()` 在 EndOfDxe 之后处理固件更新 Capsule
- **ESRT/FMP：** `UpdateEsrtFmpEntries()` 通过 EsrtManagement 协议同步 FMP 条目

### 4.6 与 USB 的交互

```c
VOID ConnectUsbControllers(BOOLEAN Recursive) {
    // 通过 PCI 类码查找 USB 控制器（Class=0x0C, SubClass=0x03）
    GetPciHandlesByClass(PCI_CL_SER_BUS, PCI_CL_SER_BUS_SCL_USB, &Number, &Handle);
    for(i=0; i<Number; i++)
        pBS->ConnectController(Handle[i], NULL, NULL, Recursive);
}
```

## 5. 数据流

### 5.1 整体引导数据流

```
[PEI Phase]
    │
    │ (HOB: MemoryTypeInformation)
    ▼
[DXE Phase]
    │ DXE Drivers 执行，PCIe/NVMe/AHCI 等设备驱动安装协议
    │
[DXE Dispatcher 完成]
    │
[BdsInit] 安装 BDS Arch Protocol
    │
[BdsEntry]
    │
    ├── 1. Read BootOrder/BootXXXX from NVRAM
    │        │
    │        ▼
    │   [BootOptionList] ← BOOT_OPTION 链表（优先级排序）
    │
    ├── 2. CollectBootDevices()
    │        │ (LoadFile / SimpleFileSystem / BBS)
    │        ▼
    │   [BootDeviceList] ← BOOT_DEVICE 链表
    │
    ├── 3. FilterBootDeviceList() → 删除不符合条件的设备
    │
    ├── 4. Match BootOptions to BootDevices (DpMatchingFunction[])
    │        │
    │        ▼
    │   每个 BOOT_OPTION.DeviceHandle ← 匹配的 BOOT_DEVICE.Handle
    │
    ├── 5. CreateBootOptionsForNewDevices() → 新发现的设备自动创建 Boot Option
    │
    ├── 6. PreProcessBootOptions() → 孤儿选项策略
    │
    ├── 7. SortList(CompareTagThenPriority)
    │
    ├── 8. PostProcessBootOptions() → 组头处理
    │
    ├── 9. Register BdsProceedToBootCallback (Reset 链)
    │
    ├── 10. HandoffToTse() → AMITSE
    │        │
    │        ├── Set BootOptionSupport / OsIndicationsSupported NVRAM
    │        ├── Install BootManagerPolicyProtocol
    │        └── AmiPostMgr->Handshake() ← TSE Boot Manager UI
    │
    │        [用户选择 Boot Option 或 自动引导]
    │              │
    │              ▼
    └── ReadBootOptionAndBoot()
              │
              ├── Boot(Option, Number, Size)
              │        ├── BootEfi() → LoadImage → StartImage (UEFI OS Loader)
              │        └── BootLegacy() → LegacyBios->LegacyBoot() (CSM)
              │
              └── [OS Loader 获得控制权]
```

### 5.2 关键变量数据流

| NVRAM 变量 | 用途 | 读取/写入 |
|-----------|------|----------|
| `BootOrder` | BootXXXX 的顺序列表 | 读 |
| `BootXXXX` | 每个启动选项的完整描述 | 读/写（固件创建新选项时） |
| `Timeout` | 等待用户选择的时间（秒） | 读/初始化 |
| `ConOut/ConIn/ConErr` | 控制台设备路径 | 读/连接 |
| `ConOutDev/ConInDev` | 控制台设备路径（已配置） | 读 |
| `DriverOrder/DriverXXXX` | 驱动加载顺序 | 读 |
| `SysPrepOrder/SysPrepXXXX` | SysPrep 应用 | 读 |
| `MemoryTypeInformation` | 内存类型配额（运行时内存） | 写（首次或内存变化时） |
| `PreviousMemoryTypeInformation` | 上次引导的内存配额 | 读/写 |
| `BootOptionSupport` | Boot Manager 能力标志 | 写（HandoffToTse） |
| `OsIndicationsSupported` | 支持的 OS Indication | 写（HandoffToTse） |

### 5.3 关键协议数据流

```
BDS 安装的协议：
  ├── gEfiBdsArchProtocolGuid
  │       └── BdsEntry 入口
  ├── gAmiBdsConnectPolicyProtocolGuid
  │       └── SetDevicePathPolicy / SetDeviceClassPolicy
  │               控制 OpROM、DriverXXXX、引导选项策略
  └── gAmiResetRequestProtocolGuid
          └── BdsRequestSystemReset → BdsSystemResetScheduled=TRUE

BDS 调用的协议：
  ├── gEfiPciRootBridgeIoProtocolGuid (LocateHandleBuffer)

  ├── gEfiSimpleFileSystemProtocolGuid (枚举 Boot 设备)
  ├── gEfiLoadFileProtocolGuid (Shell/网络引导)
  ├── gEfiDevicePathProtocolGuid (设备路径匹配)
  ├── gEfiLoadedImageProtocolGuid (检查镜像类型)
  ├── gEfiLegacyBiosProtocolGuid (传统引导)
  ├── gEfiBootManagerPolicyProtocolGuid (安装，供 TSE 使用)
  ├── gAmiPauseProtocolGuid (暂停支持)
  ├── gAmiPostMgrProtocolGuid (TSE 交接)
  ├── gEsrtManagementProtocolGuid (ESRT/FMP)

```
