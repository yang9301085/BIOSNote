# NVMe 首启问题调试

**状态**: 进行中
**平台**: PBX6000 (Intel Elkhart Lake)
**日期**: 2026-03-16 ~ 2026-03-17

---

## 问题描述

### 现象
- 清 CMOS 后第一次启动，机器直接进 Shell，NVMe 找不到
- 之后再 reset 才正常进入系统
- Cold reset 后 NVMe 丢失，Warm reset 后 NVMe 正常

### 关键特征
- `gAmiNvmeControllerProtocolGuid` 协议在首启时找不到
- RU 工具里连 PCI device list 都看不到 NVMe

#### 发现的两个独立问题

**问题 A：首启自动重启**
- 原因：BDS 的 `SaveMemoryTypeInformation()` 检测到首启时 runtime memory type 发生变化
- 机制：`PcdResetOnMemoryTypeInformationChange` 打开时，BDS 会自动 reset 让新配额生效
- 结论：这是正常行为，与 NVMe 问题无关
- 详见：[[首启自动 Reset 机制 (BDS Memory Type Information)]]

**问题 B：Cold reset 找不到 NVMe，Warm reset 能找到**
- 现象：RU 工具里连 PCI device list 都看不到 NVMe
- 结论：问题在 PCIe 枚举层，不是 `gAmiNvmeControllerProtocolGuid` 协议层
- 推测：M.2 SSD 的上电/PERST#/REFCLK/CLKREQ#/link training 在 cold reset 时序上不稳定

---

### 第二阶段：深入分析 Cold/Warm Reset 差异

通过 Codex 会话深入分析了 CF9 寄存器机制：

#### CF9 寄存器值定义

| 名称 | 值 | 作用 |
|---|---:|---|
| `SOFTSTARTSTATE` | `0x00` | 选择软启动状态 |
| `HARDSTARTSTATE` | `0x02` | 选择硬启动状态 |
| `HARDRESET` | `0x06` | 触发硬复位 |
| `FULLRESET` | `0x0E` | 触发全复位 (含 power cycle) |

#### 本平台实际路径

- `EfiResetWarm`: `0x00 -> 0x06` (Soft Start State -> Hard Reset)
- `EfiResetCold`: `0x02 -> 0x0E` (Hard Start State -> Full Reset)

因为 `COLD_RESET_WITH_POWER_CYCLE=1` (见 `Sb.sdl:3441`)

详见：[[Cold Reset vs Warm Reset (Intel PCH CF9 寄存器)]]

---

### 第三阶段：建立工作模型

```
Cold Reset 路径:
BDS 检测首启 -> EfiResetCold -> CF9: 0x02 -> 0x0E
    ↓
M.2/PCIe 更接近"彻底冷起"状态
- 设备重新上电
- PERST#/REFCLK/CLKREQ# 重新走时序
- Root Port 重新训练链路
    ↓
如果任何一步不稳 -> PCI 枚举看不到 NVMe endpoint

Warm Reset 路径:
Shell/键盘触发 -> EfiResetWarm -> CF9: 0x00 -> 0x06
    ↓
平台/设备保留更多"非彻底冷起"状态
    ↓
M.2 SSD 更容易被枚举
```

---

## 当前结论

### 根因定位

问题在 PCIe/M.2 枚举层，不是 NVMe 协议层：
- PCI 枚举阶段就看不到 NVMe endpoint
- NVMe driver 没有 PciIo 可以 bind
- `gAmiNvmeControllerProtocolGuid` 丢失只是表象

### 可能原因

设备上电/复位时序在 cold reset 条件下不稳定：
- PERST# 信号时序
- REFCLK 时钟
- CLKREQ# 信号
- 电源轨上电时序
- PCIe 链路训练

---

## 下一步

### 需要验证的假设
- PERST#/REFCLK/CLKREQ#/链路训练是否稳定
- Root Port 在 cold reset 后的状态

### 建议调试手段
1. **寄存器检查**: cold reset 后检查 Root Port 状态寄存器
2. **示波器测量**: PERST#、REFCLK、CLKREQ# 信号时序
3. **PCIe 链路训练**: 检查 Link Training 状态

### 可能的解决方案
- 检查 M.2 插槽的电源时序
- 检查 PERST# 信号的上拉/下拉
- 检查 PCIe 链路训练的等待时间
- 考虑在 PEI/DXE 阶段增加 PCIe 设备初始化的延迟
