## NVMe 首启调试会话

### 问题现象
清 CMOS 后第一次启动，机器直接进 Shell，NVMe 找不到；之后再 reset 才正常进入系统。

### 调试过程

#### 1. 新增公共库 YqrSerialPrintLib
- 头文件：`AmiModulePkg/Include/Library/YqrSerialPrintLib.h`
- 源文件：`AmiModulePkg/Library/YqrSerialPrintLib/YqrSerialPrintLib.c`
- INF：`AmiModulePkg/Library/YqrSerialPrintLib/YqrSerialPrintLib.inf`
- 接口：`BiosSerialWrite()`, `BiosSerialPrintf()`
- 目的：在任意模块中都能方便地往串口输出调试信息

#### 2. 在 NVMe 模块和 BDS 中加串口日志
- `NvmeDynamicSetup.c` — 关键步骤日志
- `NvmeBus.c` — 协议跟踪日志
- `Bds.c` — memory type information 相关日志
- `OemDxe.c` — PCI 枚举判定

#### 3. 发现的两个独立问题

**问题 A：首启自动重启**
- 原因：BDS 的 `SaveMemoryTypeInformation()` 检测到首启时 runtime memory type 发生变化
- 机制：`PcdResetOnMemoryTypeInformationChange` 打开时，BDS 会自动 reset 让新配额生效
- 结论：这是正常行为，与 NVMe 问题无关

**问题 B：Cold reset 找不到 NVMe，Warm reset 能找到**
- 现象：RU 工具里连 PCI device list 都看不到 NVMe
- 结论：问题在 PCIe 枚举层，不是 `gAmiNvmeControllerProtocolGuid` 协议层
- 推测：M.2 SSD 的上电/PERST#/REFCLK/CLKREQ#/link training 在 cold reset 时序上不稳定

### 关键结论
1. 首启第一次自动重启是 BDS memory type 机制触发的
2. NVMe 丢失问题已收敛到 PCIe/M.2 枚举层，更像板级时序问题

### 下一步
不再追 `gAmiNvmeControllerProtocolGuid`，直接看 Root Port 状态：
- Root Port BDF
- Secondary/Subordinate Bus
- Link Status
- 下游 Vendor ID / Device ID
- 确认是链路没起来、bus 没分配、还是 endpoint 返回 0xFFFF
